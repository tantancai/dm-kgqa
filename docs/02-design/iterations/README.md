# 每期开发设计书

每一期（V1 / V2a / V2b / V3）开工前写一份 `<期次>-design.md`，按下面的模板填写。**状态为"已批准"之后，才能开始写代码**。各章对应设计审核关卡 G3～G6，可以分章提交审核。

**工作量大的一期拆成"总设计 + 分阶段设计"**（V1 起采用）：
- 总设计 `<期次>-design.md`：只定跨阶段不变的内容，包括范围、子阶段划分与退出标准、模块边界、**模块之间的接口**、主流程、评测目标、端到端用例清单。开工前审批。
- 分阶段设计 `<期次>.<n>-design.md`：每个子阶段开工前写、开工前审批，只细化模块内部，**不得改动总设计中的接口**；确需改动，先报备，并同步修改总设计。
- 分阶段设计沿用下面的模板，与总设计重复的章节写"见总设计第 x 节"即可。

## 模板

```markdown
# <期次> 开发设计书

- 状态：草稿 / 待审 / 已批准（YYYY-MM-DD）
- 对应需求：REQ-xx, REQ-yy …
- 依据：architecture.md 第 x 节、ADR-xxxx

## 1. 本期目标与范围（G3）
- 做什么，不做什么
- 完成标准（与分期计划一致）

## 2. 模块设计（G3）
每个模块：职责、对外接口（函数签名 / HTTP 接口）、依赖、实现要点。

## 3. 数据结构与存储（G3）
新增或变更的数据结构、图谱查询、表结构、缓存键格式。

## 4. 关键流程（G3）
时序图或流程图，正常流程和每一个异常分支（超时、报错、空结果、取消）。

## 5. 配置项与依赖（G3）
新增的环境变量、第三方库及其版本，以及选择的理由。

## 6. 任务拆分（G3）
| 任务 | 对应 Issue | 预计工时 | 依赖 |
每个任务对应一个 Issue 和一个 PR，粒度控制在 0.5～2 天。

## 7. 评测目标（G4）
| 指标 | 对照组 | 目标值 | 依据 |
测试集版本、评测方法，以及达不到目标时怎么办。

## 8. 端到端测试（G5）
| 用户路径 | 步骤 | 期望结果 | 自动化 / 手动 |
覆盖正常提问、口语、多跳、无答案、拒答、断开取消等路径。

## 9. 前端设计（G6，涉及前端时）
页面清单、交互流程、各种状态（加载中 / 流式输出中 / 出错 / 拒答 / 无答案）的样式，**附可以直接查看的原型**（放在 `iterations/<期次>-ui/`）。

## 10. 风险与待决问题
| 风险 / 问题 | 影响 | 预案 / 需要谁决定 |
```
