# V1.1 审核表复审提示词

- 状态：**已批准**（2026-11-04）
- 用途：把 `kg/work/review/` 下的三张审核表交给另一个模型做复审（交叉审核）。复审结果写入审核表的"复审结论"列，再按 v1.1-design 第 5 节的流程处理。
- 三张表：`alias`（别名）、`drug_relation`（药物—疾病关系）、`diet`（饮食知识）。

## 0. 使用方法

1. 每次发送 **一段提示词 + 30～50 行数据**。行数太多，模型容易漏行或串行。
2. 数据以 JSON Lines 格式粘贴，每行一个对象，字段名和审核表的列名一致。导出脚本会额外生成一份同名的 `.jsonl` 文件，直接复制即可。
3. 模型输出也是 JSON Lines，用 `python -m kg review merge <表名> <输出文件>` 合并回审核表。脚本会检查：行数是否对得上、`id` 是否都存在、取值是否合法。不合格的整批退回重发。
4. **推荐的分工**（保留人工抽检的效力，REQ-25）：
   - 复审结论与预标**一致**的：从中随机抽 10% 由你确认（2026-11-03 确认）。**如果这 10% 里错误率超过 5%**，说明复审模型不够可靠，该表一致项的抽检比例提高到 30%，并换一个复审模型重跑一次。
   - 复审结论与预标**不一致**，或复审给出"存疑"的：**全部由你确认**。
   - 禁用 / 慎用边如果复审与预标一致，按抽检处理；不一致的全部由你看。
   - 通过率统计以**你的结论**为准。论文中写"LLM 预标 → 异构模型交叉复审 → 人工裁决分歧项并抽检一致项"。
5. 复审模型必须和预标模型**不是同一家**。预标用 DeepSeek，复审建议用通义千问、Kimi、GPT 或 Claude 中的一个，评测报告中注明模型名和版本。

## 1. 别名表 `alias`

```text
你是医学术语标准化审核员。下面每行是一条"别名 → 规范名"的候选映射，来自糖尿病临床指南的实体标注数据。请逐行判断这条映射是否成立。

【判断标准】
- "对"：别名与规范名指的是**同一个医学概念**，范围不变。例如 T2DM → 2型糖尿病；HbA1c → 糖化血红蛋白；磺脉类药物 → 磺脲类（错别字）。
- "错"：两者不是同一概念，或范围不同。重点检查以下错误：
  1. 泛化或窄化：T2DM → 糖尿病（错，应为 2型糖尿病）；糖尿病肾病 → 肾病（错）。
  2. 缩写对错概念：同一缩写在医学中有多种含义时，以"例句"中的用法为准。例如 DN 在例句中指糖尿病肾病还是糖尿病神经病变。
  3. 把并列的两个概念合成一个：如"高血压和高血脂"不能映射到其中一个。
  4. 规范名本身写错（错别字、多余后缀"药物""类药"等）。
- "存疑"：例句信息不足以判断，或你不确定。**拿不准一律选存疑，不要猜。**

【输入字段】
id、label（实体类型）、alias（别名）、canonical（拟定的规范名）、source（rule/llm）、example（含该别名的一句原文）

【输出要求】
每个输入行输出一行 JSON，不要输出其他文字：
{"id": "...", "verdict": "对|错|存疑", "fix": "verdict 为错时给出正确的规范名，否则为 null", "reason": "不超过 30 字"}
- 输出行数必须与输入行数相同，顺序一致。
- fix 只能写一个医学概念名称；不知道正确答案时，verdict 改为"存疑"。

【数据】
<在此粘贴 30～50 行 JSONL>
```

## 2. 药物—疾病关系表 `drug_relation`

```text
你是临床药学审核员。下面每行是从糖尿病临床指南中抽取的一条"药物—疾病"关系，已由另一个模型预先打了标签。请**只依据该行给出的原句**，判断预标是否正确。不要使用原句以外的医学知识补充或纠正结论；原句没有说的，就当作不知道。

【四种标签的定义】
- INDICATED（适用）：原句表明该药可用于、推荐用于、首选用于该疾病或人群。例："二甲双胍是 T2DM 患者控制高血糖的一线用药"。
- CONTRAINDICATED（禁用）：原句表明在该疾病或状态下禁用、禁忌、不应 / 不宜 / 不得使用、应停用。例："eGFR<30 ml/min 时禁用二甲双胍"。
- CAUTION（慎用）：原句表明可以用但需谨慎，包括慎用、需减量、需调整剂量、需监测、不推荐 / 不建议（但没有说禁用）。例："肾功能不全者慎用磺脲类"。
- MENTION（仅提及）：原句只是同时提到两者，没有表达"能不能用"的判断。包括：药物**导致**该疾病（如"磺脲类可引起低血糖"，这是不良反应，不是适应证）、研究背景、机制描述、列举。

【判断规则】
1. 方向：判断的是"该药物对该疾病 / 人群能不能用"。如果原句中该疾病是药物的不良后果，标签应为 MENTION。
2. 同一句里有多个药物或疾病时，只判断本行给出的这一对，不要被同句中其他药物的结论带偏。
3. 否定和条件要读全："除……外""仅在……时""不建议首选"会改变标签。
4. condition（适用条件）必须来自原句，例如"eGFR<30 ml/min 时""妊娠期"。原句有条件而预标漏了，或预标的条件不是原句里的，都算"错"。
5. quote（引文）必须能支持该标签。
6. 拿不准、原句表述有歧义的，选"存疑"。**禁用和慎用的判断关系到用药安全，宁可存疑，也不要猜。**

【输入字段】
id、drug、disease、sentence（原句）、label（预标标签）、condition（预标条件，可为 null）、quote（预标引文）

【输出要求】
每个输入行输出一行 JSON，不要输出其他文字：
{"id": "...", "verdict": "对|错|存疑", "fix_label": "verdict 为错时给出正确标签，否则为 null", "fix_condition": "条件有误时给出原句中的正确条件，无条件写 \"\"，条件没问题写 null", "evidence": "支持你判断的原句片段，必须是 sentence 的原文子串", "reason": "不超过 30 字"}
- 输出行数必须与输入行数相同，顺序一致。
- evidence 必须逐字摘自 sentence，不能改写。

【数据】
<在此粘贴 30～50 行 JSONL>
```

## 3. 饮食知识表 `diet`

```text
你是临床营养审核员。下面每行是从《中国糖尿病防治指南（2024 版）》或《成人糖尿病食养指南（2023 年版）》中抽取的一条饮食知识。请**只依据该行给出的原句**判断抽取是否正确，不要使用原句以外的知识。

【记录类型】
A. type = "rel"：食物（或饮食原则）与疾病 / 人群的关系，rel 取值：
   - RECOMMENDED_FOR（推荐）：原句表示推荐、宜选、优选、多吃、适量增加。例："优选全谷物"。
   - LIMITED_FOR（限量）：原句表示控制量、限量、减少、适量、注意时机或搭配，但没有要求完全不吃。例："严格控制蔗糖、果糖制品的摄入"属于限量。
   - AVOIDED_IN（避免）：原句表示避免、不宜、忌、不建议食用。例："避免饮用含糖饮料"。
   - TREATED_BY（饮食原则）：疾病 → 饮食干预原则，如"医学营养治疗""控制总能量"。
B. type = "gi"：食物的血糖生成指数分级，gi_level 取值：低 / 中 / 高。原句一般是表格中的一行或一段，判断该食物在原文中是否确实属于该分级。

【判断规则】
1. head（食物）必须是原句中出现的食物或食物类别，不能把类别擅自缩小成具体食物（原句说"水果"，不能写成"苹果"），也不能放大。
2. 限量和避免要区分清楚："少吃""控制"是限量；"避免""不宜"是避免。
3. 条件（condition）必须来自原句，例如"血糖控制良好时""两餐之间"。
4. 原句是按中医证型推荐食材的，或者是成套食谱、食物交换份量的，这类内容本不该被抽取，verdict 判"错"，reason 写"不在抽取范围"。
5. 拿不准的选"存疑"。

【输入字段】
id、type、head、rel、tail、gi_level、condition、sentence（原句）、doc（出处文档）、page（页码）

【输出要求】
每个输入行输出一行 JSON，不要输出其他文字：
{"id": "...", "verdict": "对|错|存疑", "fix": {"head": null, "rel": null, "gi_level": null, "condition": null}, "evidence": "原句中的支持片段，逐字摘录", "reason": "不超过 30 字"}
- fix 里只填需要改的字段，其余保持 null。
- 输出行数必须与输入行数相同，顺序一致。

【数据】
<在此粘贴 30～50 行 JSONL>
```

## 4. 和预标提示词的关系

上面第 2、3 节的**标签定义**，同时就是 `refine` 和 `diet` 两步给 DeepSeek 做预标时用的定义，两边逐字保持一致。改定义时两边一起改，并在审核表里记录提示词版本。否则预标和复审依据的标准不同，"不一致"的统计就失去意义。

**已定的一处定义**（2026-11-04）：原句中"不推荐 / 不建议使用某药"归为 **CAUTION（慎用）**，不归为禁用，理由是原句没有说禁止。回答时提示"慎用、请遵医嘱"。
