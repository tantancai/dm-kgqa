## 1. 目标与退出标准

**交付物**：`kg/` 六步流水线脚本 + 单元测试；`kg/data/` 下四份审核过的数据文件和 `LICENSE.md`；`kg/schema.yaml`；图谱统计报告；Neo4j 中的 `kg-v1` 图谱。

**退出标准**（总设计第 2 节）：
1. 图谱打 tag `kg-v1`，统计报告附在 PR 里。
2. 人工审核通过率 ≥ 95%：禁用 / 慎用边全审；其余药物边抽 20%（REQ-25）。
3. 第 7 节构建自检全部通过。
4. `python -m kg all` 在空库上从头跑完，结果和已提交的数据文件一致（可复现）。

**不做**：问答链路的任何代码（V1.2）；`ai_service/` 目录在本阶段不建。

### 3.1 命令
| 命令 | 做什么 | 调 LLM | 需要人工 |
|---|---|---|---|

| `drug-class` | ② 第 4 小步：药物类别，按附录 A.5 归类，导出汇总和存疑表 | 是（规则覆盖不到的） | 否（存疑项交导师） |

`all` 不调 LLM，是可复现性的关键：别人拿到仓库和 DiaKG 原始数据，就能重建出同一个图谱。

### 3.2 LLM 调用
- **为什么不复用 `ai_service/llm/`**：总设计第 3 节规定 `kg` 与 `ai_service` 不互相 import，而且 `ai_service` 要到 V1.2 才建。`kg/llm.py` 只有一个函数 `chat_json(prompt) -> dict`，约 50 行，用 httpx 调 DeepSeek。DeepSeek 只支持 `json_object`，不支持按 JSON Schema 约束，所以去掉了原设计的 `schema` 参数，结构校验由各步调用方负责（T3 实现时调整）。
- **缓存**：以"模型名 + 提示词 + 输入"的哈希为键，响应存到 `work/llm_cache/`。重跑不重复花钱；改提示词后只重跑受影响的条目。
- **参数**：temperature 0；JSON 输出；超时 30s；失败重试 2 次，仍失败的条目记录下来，进人工审核表。
- **成本估算**：③ 约 1,500 次调用、④ 约 100 段，② 判同约几百次，合计约 1～2M token。按 DeepSeek 公开价格估算在几元到十几元之间（价格我没有现场查证，以官网为准）。
- **需要你做**：第 2 周前把 DeepSeek API Key 写进本地 `.env` 的 `DEEPSEEK_API_KEY`，不要发在对话里。

## 4. 各步实现要点

### ① load
- 句子 ID：`diakg-<doc_id>-<paragraph_id>-<sentence_id>`；实体出现 ID 在句子 ID 后加 `-T<n>`。
- DiaKG 结构已核对：41 个文件，3,498 句；字段为 `doc_id / paragraphs[].sentences[].entities[] / relations[]`，关系以 `head_entity_id`、`tail_entity_id` 引用同一句中的实体。
- 关系方向按 data-model 2.2 节统一，比如 Drug_Disease 的 head 是 Drug。原始数据方向和预期不一致的边计数并报告，不静默纠正。

### ② normalize
- 括号拆分、缩写映射、写法统一、长短语处理，按 data-model 第 ② 步的顺序执行。
- 相似度聚类用 RapidFuzz：同一 label 内，编辑相似度 ≥ 0.85 的名称归为一个候选组，交给 LLM 判断"是否同一概念"，并给出规范名。阈值是初始值，按第一轮结果调整。
- `T2DM → 2型糖尿病`、`T1DM → 1型糖尿病` 这类"不能映射到更泛概念"的规则，写成单元测试固定下来。

### ② drug-class
- 先用关键词（"类""抑制剂""激动剂""促泌剂""增敏剂""阻滞剂""拮抗剂"）把类别名从 Drug 中分出来，再用别名表合并错别字（如"磺脉类""映岛素促泌剂"）。
- 标准类别清单先由我按 2024 版指南的降糖药分类列出草案（双胍类、磺脲类、格列奈类、α-糖苷酶抑制剂、TZD、DPP-4i、SGLT2i、GLP-1RA、胰岛素及类似物等），**你在审核表里确认**。非降糖药类别（他汀、ARB、β 受体阻滞剂等）保留，但只合并写法，不做细分。
- 具体药名：词根规则优先（如"列汀"→ DPP-4 抑制剂、"格列净"→ SGLT2 抑制剂、"格列"开头且非"格列奈"→ 磺脲类），剩下的交给 LLM 预标。

### ③ refine
- 一条边调用一次 LLM，输入"药物、疾病、原句"，输出 `{label, condition, quote}`（data-model 第 ③ 步）。
- `quote` 不是原句子串的、LLM 调用失败的、label 不在白名单的，标记为 `needs_manual`，在审核表中置顶。
- 抽样：INDICATED 和 MENTION 两类用固定随机种子抽 20%，保证重跑时抽到的是同一批。

### ④ diet
- **PDF 切句**：用 PyMuPDF 按页取文字；去掉页眉页脚（如"中华糖尿病杂志 2025 年1 月…"）和参考文献角标；把跨行断开的句子接起来；按"。；"切句。页码范围写在 `config.py`，例如防治指南"医学营养治疗"在 PDF 第 18～20 页。
- 句子 ID：防治指南为 `g24-p<页>-<n>`，食养指南为 `fg23-p<页>-<n>`。
- **GI 表**：先尝试从附录 1 表 1.1 自动提取；提取结果不完整时，改为人工对照 PDF 录入。GI 数据以 `{"type": "gi", "food", "gi_level", "sid"}` 写进 `diet_triples.jsonl`，不另建新文件。
- 抽取范围和"不抽取"清单按 data-model 第 ④ 步执行。

### ⑤ build
- 以 `neo4j` 账号、**写事务**执行；只有这一步写库。问答服务（V1.2）一律用读事务。
- 分批 `UNWIND $rows AS r MERGE …`，每批 500 行。
- `--reset`：先 `MATCH (n) DETACH DELETE n`，再删除约束和索引后重建。社区版只有一个用户库，所以不能用"新建一个库"的方式。
- 关系属性 `reviewed` 来自审核表：抽中并审核通过为 true，未抽中为 false。

### ⑥ stats
- 报告内容按 data-model 第 ⑥ 步。另外附上四份数据文件的 SHA-256 和当前 commit 哈希，用来对应 `kg-v1` tag。

## 5. 人工审核流程

### 5.1 流程

**交叉复审**（2026-11-02 新增）：别名、药物关系、饮食三张表先交给另一家模型复审，提示词见 `v1.1-review-prompts.md`。之后你只需确认两类行：复审与预标**不一致**或复审为"存疑"的（全部），以及一致的行中随机抽取的 10%。通过率以你的结论为准，因此仍满足 REQ-25 的人工抽检要求。

1. 运行某一步（如 `refine`），生成 `kg/work/review/<表名>.xlsx`。
2. 你在 Excel 里填"结论"列，可选值为 **对 / 错 / 存疑**（下拉框）；选"错"时在"改为"列填正确值。
3. 运行 `python -m kg review import <表名>`。脚本校验需要你确认的行都已填写，确定每行最终结论，写到 `kg/work/review/<表名>.decided.jsonl` 并打印通过率；各步（normalize、refine、diet）再把它转换成 `kg/data/` 下对应的文件（T3 实现时调整：审核模块与具体表无关）。
4. 通过率 < 95% 时：我按错误类型改提示词或规则，重跑，**已审过的行保留你的结论，只有改动过的行重新进表**。
5. "存疑"的行单独汇总成一张表，交导师判断。导师结论出来之前，这些行**按不通过计算**，且不写入图谱。

**通过率** = 对 /（对 + 错 + 存疑）。

### 5.2 四张审核表
| 表 | 主要列 | 排序方式 | 预计条数 | 安排在 |
|---|---|---|---|---|
| `alias` | label、别名、规范名、来源（rule/llm）、结论、改为 | 按规范名分组 | 150～250 | 第 2 周 |
| `drug_class` | 药名、建议类别、依据（guideline / rule / llm）、证据句 | 按类别分组 | **你不审**：按附录 A.5 依指南核对；`llm` 来源的全部交导师 | 第 2 周 |
| `drug_relation` | 药物、疾病、原句（高亮药名和病名）、LLM 标签、条件、引文、结论、改为 | `needs_manual` 置顶，再按标签分组 | 禁用 / 慎用约 300～400 全审 + 抽样约 220 | 第 3 周 |
| `diet` | 食物、关系 / GI 分级、疾病、条件、原句、出处页码、结论、改为 | 按出处文档和页码 | 150～300 | 第 4 周 |

合计约 6～9 小时（药物类别改为依据指南核对后，比 data-model 原估算少约 2 小时，data-model 第 5 节已同步）。

## 7. 测试与构建自检

### 7.1 单元测试（`tests/kg/`，不需要 Neo4j）
| 测试 | 断言 |
|---|---|
| 括号拆分 | `糖尿病周围神经病(diabetic peripheral neuropathy，DPN)` → 规范名 + 两个别名；全角、半角括号都能处理 |
| 缩写不泛化 | `T2DM` 只映射到 `2型糖尿病` |
| 引文校验 | `quote` 是原句子串才通过；只差空格或全角半角不同也算不通过（严格匹配） |
| 药物词根规则 | "西格列汀"→ DPP-4 抑制剂；"格列美脲"→ 磺脲类；"瑞格列奈"→ 格列奈类 |
| 切句 | 去掉页眉，跨行句子能接上 |
| 审核导入 | 有空结论时报错；"错"但"改为"为空时报错 |
| 剂量过滤 | Amount / Frequency / Duration 不出现在待建图数据中 |

### 7.2 构建自检（`build` 结束时自动运行，任何一项失败则 build 失败）
1. 每条关系 `size(r.sids) ≥ 1`，且每个 sid 都有对应的 `Sentence` 节点。
2. 图中不存在剂量类数据。
3. `alias.csv` 中前 60 个高频缩写，全部能通过全文索引查到对应实体。
4. 不存在 `reviewed = false` 的 `CONTRAINDICATED_IN` / `CAUTION_IN` 边（这两类必须全审）。
5. **幂等**：连续跑两次 `build`，节点数和边数不变。
6. `MENTIONED_WITH` 边数和审核表中的数量一致。

### 7.3 集成测试
`tests/kg/test_build.py`：在 Neo4j 上用约 20 句的小样本数据跑一次 `build`，检查 7.2 的各项。需要本机 Neo4j 在运行；运行不了时自动跳过，并注明原因。

## 附录 A：标准药物类别清单（已定，2026-11-02）

**依据**：类别名和归属全部以《中国糖尿病防治指南（2024 版）》原文为准，括号内为指南原文用语和定位。DiaKG 里的各种写法（如"磺脲类药物""磺脉类""CLP-1受体激动剂""预混胰素类似物"）作为别名合并进对应类别。

**实现方式**：一个药物可以 `BELONGS_TO` 多个类别，例如格列美脲同时属于"磺脲类"和"胰岛素促泌剂"。不新增类别之间的关系，data-model 的 Schema 不变。

### A.2 胰岛素子类（照抄指南的 8 类）

超短效胰岛素类似物（DiaKG 写作"速效胰岛素类似物"，作别名）、短效胰岛素、中效胰岛素、长效胰岛素、长效胰岛素类似物（含周制剂）、预混胰岛素、预混胰岛素类似物、双胰岛素类似物。每个子类同时属于"胰岛素"。
另按指南"基础胰岛素包括中效胰岛素和长效胰岛素类似物"，把这两类同时归入"基础胰岛素"。

### A.4 特殊写法的处理（已定）

| 写法 | 处理 |
|---|---|
| 胰岛素增敏剂 | 作为 TZD 的别名（2024 版指南未使用此说法） |
| 磺胺类药物 | 看原句：是"磺脲类"的错别字就合并，是抗菌药就归入非降糖药 |
| 非促泌剂类、非胰岛素促泌剂 | 否定类别，不建节点，只保留在原句中 |
| 第一代 / 第二代磺脲类 | 合并进磺脲类，作为别名 |

### A.5 药物归类的核对方式

药物 → 类别的映射（`drug_class.csv`）按以下顺序确定，**不需要你逐条审核**：
1. 药名出现在上表"指南列出的药物"中 → 直接按表归类，`source = guideline`。
2. 不在表中、但词根规则能判断（如"××格列汀"）→ 按规则归类，`source = rule`；同时检索指南原文，找到"药名 + 类别名"同句出现的句子作为证据。
3. 前两步都判断不了 → LLM 预标，`source = llm`，**全部列入"存疑"表交导师确认**，确认前不写入图谱。

你只需看一份汇总：各类别的药物数，以及存疑表的条数。
