# ADR-0008：级别 3 由多跳 Agent 改为图邻域证据回退，并借鉴引用校验和约束抽取

- 状态：已采纳
- 日期：2026-10-30
- 关联：REQ-04、REQ-24、REQ-27；取代 architecture.md 原"级别 3 多跳 Agent（可选）"

## 背景

Text2Cypher 擅长事实型问题（"二甲双胍禁用于哪些情况"）。遇到开放式问题（"糖尿病早餐吃什么好"），它经常查空，只能返回 NO_INFO，这对 ToC 用户体验伤害最大。参考腾讯 WeKnora（v0.9.0，MIT）的 GraphRAG：它用 LLM 抽取问题中的实体，按 `CONTAINS` 匹配节点，取一跳邻居挂载的文本块，作为向量检索的补充召回，再统一重排。WeKnora 的图谱只负责召回、不直接给出答案，和本项目"结构化查询直接出答案"的思路正好互补。

## 可选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 级别 3 做多跳 Agent | 有望提高多跳题的 F1；Agent 话题热度高 | 每题要调多次 LLM，和 V2a 的"省资源"主题相反；医疗场景下自主多轮推理的风险更高；开放式问题仍然答不了 |
| B. 级别 3 做图邻域证据回退 | 补上开放式问题；回答被限定在指南原句上，并带引用；只在查空时多调一次 LLM；DiaKG 每条边自带原句，几乎不需要新数据 | 回退通道的答案不是实体集合，无法计算实体 F1 |
| C. 两者都做 | 覆盖最全 | 工期不允许，而且现在没有数据证明 Agent 有必要 |

## 决定

选 B，作为 V2a 的 P1。多跳 Agent 降为 P2：只有 V1 错误分析显示，多跳题失败的原因是"一条 Cypher 表达不了"时才做。

另外从 WeKnora 借鉴两点，都不增加工期：
1. **引用校验**（V1）：每条证据带编号，回答以编号内联引用，生成后删除不存在的编号。
2. **约束抽取与幂等写入**（V1，REQ-24 饮食知识）：限定实体类型、关系类型并给出示例；用 MERGE 幂等写入；同一实体出现在多处时合并出处。

## 理由与代价

- 和 WeKnora 的区别：本项目以精确查询为主，邻域召回只做兜底；实体链接用全文索引加别名表，不用 `CONTAINS`，因为 WeKnora 自己的文档也承认短名称容易误匹配。
- 评测口径不变：实体 F1 只统计级别 0～2 的结果；级别 3 单独报告回退命中率（回退后不再返回 NO_INFO 的比例）和引用正确率（人工抽检引用的原句是否支撑回答）。
- 接口契约做了向后兼容的扩展：`EvidencePath` 新增可选字段 `id`、`source`；`route_level=3` 的含义改为"证据回退"。
- 代价：多跳题的 F1 只能靠 Text2Cypher 本身（两跳查询加多跳示例）来提高。
