# ADR-0004：多家 LLM API 的切换放在 AI 服务，而不是网关

- 状态：已采纳
- 日期：2026-10-29
- 关联：REQ-21

## 背景

V2b 要同时接入 DeepSeek 和通义，一家超时或被限流时自动切换到另一家。需要决定这部分逻辑放在网关还是 AI 服务里。

## 可选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 放在网关：AI 服务通过网关代理调用 LLM | 所有外部流量都经过网关，便于统一管理 | AI 服务调用模型要绕回网关，链路变长；V3 换网关时还要重写模型代理 |
| B. 放在 AI 服务的 LLM 适配层 | 调用模型的地方就是切换的地方，逻辑集中 | 网关看不到具体用了哪家模型（通过遥测字段补上） |

## 决定

选 B。网关只做用户级调度（谁先进、放行多少、忙时谁降级），**不直接调用 LLM**；通过限制放行到 AI 服务的并发数，间接控制模型的并发量。

## 理由与代价

- 职责划分清楚：网关管"人"，AI 服务管"模型"。
- V3 换网关时不涉及模型调用逻辑，两版网关的对比更干净。
- 代价：网关不知道每家模型 API 的实时状态，只能根据 AI 服务返回的 `BUSY` 和时延来调整放行数。
