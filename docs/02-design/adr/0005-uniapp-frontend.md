# ADR-0005：前端用 uni-app，一套代码编译成 H5 和微信小程序

- 状态：已采纳
- 日期：2026-10-29
- 关联：REQ-08、REQ-16

## 背景

产品是 ToC 形态，用户主要在手机上使用。开发、演示和答辩希望用 H5，真实用户试用时希望能用微信小程序。

## 可选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 普通 Web（Vue / React）只做 H5 | 最简单 | 想做小程序就得重写一遍 |
| B. 原生微信小程序 | 小程序体验最好 | 演示和答辩不便，H5 要另写一套 |
| C. uni-app（Vue 3） | 一套代码编译成 H5 和小程序 | 两端有少量差异需要处理（主要是流式接收） |

## 决定

选 C。默认发布 H5，试用时再编译成小程序。

## 理由与代价

- 小程序可能卡在三道门槛上：域名需 HTTPS 并完成 ICP 备案、个人主体不能选医疗类目、需要体验成员名单。走不通时可以直接退回 H5，代码不用改。
- 主要差异在流式接收：H5 用 `fetch` 读流；小程序不支持 `EventSource`，要用 `wx.request` 开启 `enableChunked`，在 `onChunkReceived` 回调里处理。两端共用同一个 SSE 解析函数，**服务端不用为小程序改动**。
- 代价：部分 uni-app 组件在两端表现不一致，要在两端分别验证。
- 待核实：上述小程序能力和类目规则以微信官方文档为准。
