# ADR-0001：V1 起网关与 AI 服务分成两个进程

- 状态：已采纳
- 日期：2026-10-29
- 关联：NFR-07、REQ-22

## 背景

版本路线中，V3 要把网关从 Python 换成 Go，并与 Python 版做对比。如果 V1 把调度和问答写在同一个进程里，到 V3 就得先拆分再重写，而且拆分时很容易破坏已有功能。

## 可选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 单进程，网关逻辑和问答逻辑写在一起 | V1 最省事 | V3 先要拆分；网关直接 import AI 模块，边界会越来越模糊 |
| B. V1 起分成两个进程，只通过 HTTP 契约通信 | V3 只替换网关；压测时可以把 AI 服务换成 Mock | V1 多一个进程，多一层转发 |

## 决定

选 B。接口写进 `contracts/openapi.yaml`，四个版本保持不变。V1 的网关只是一层很薄的转发。

## 理由与代价

- 估算下来，B 让 V3 的工作量约为 1.5～2 周；A 需要 3～4 周，而且容易出错。
- Python 网关在 V3 之后保留下来，作为对比实验的基线，并没有白写。
- 代价：V1 多一个进程，多一次本机 HTTP 转发（毫秒级，相对于秒级的模型调用可以忽略）。
- **纪律要求**：网关代码禁止 import `ai_service` 中的任何模块，只能通过 HTTP 调用。
