# ADR-0002：Text2Cypher 一律生成参数化 Cypher

- 状态：已采纳
- 日期：2026-10-29
- 关联：NFR-03、REQ-12

## 背景

LLM 生成的 Cypher 会直接在 Neo4j 上执行，存在注入风险。另外，V2a 想缓存已经生成的查询：例如"二甲双胍的禁忌"和"格列美脲的禁忌"应该能共用同一条查询。

## 可选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 实体名直接拼进语句：`{name:'二甲双胍'}` | 提示词简单 | 有注入风险；每个实体生成的语句都不同，无法缓存 |
| B. 参数化：`{name:$drug}`，实体通过参数传入 | 防注入；语句本身就是可复用的模板 | 提示词要规定参数写法，需要校验参数是否齐全 |

## 决定

选 B。实体链接得到的标准实体名作为参数传入，LLM 只负责生成语句的结构。

## 理由与代价

- 一个决定同时解决两个问题：安全（NFR-03）和 V2a 的缓存（REQ-12）。
- V2a 的缓存键 = 把问题中的实体替换成类型占位符后得到的问题签名，缓存值 = 参数化 Cypher。命中后绑定参数即可执行，不需要调用 LLM。
- 缓存的是查询语句而不是答案，图谱更新后重新执行就能拿到新结果，不会返回过时答案。
- 代价：生成后要校验参数是否和已链接的实体一一对应；不对应就视为生成失败，走重写流程。
