# 测试计划

> 状态：初稿 · 2026-10-29 · V1 第 11 周冻结测试集前修订
> 关联：REQ-10、NFR-01、NFR-02、ADR-0006

## 1. 测试分层

| 层次 | 测什么 | 工具 | 何时运行 |
|---|---|---|---|
| 单元测试 | Cypher 只读校验、参数校验、SSE 解析、限流、优先级队列 | pytest / go test | 每个 PR（CI 自动运行） |
| 接口测试 | 按契约检查事件顺序和字段，以及 4 种错误码 | pytest + httpx | 每个 PR |
| 护栏测试 | 诊断、剂量类问题全部拒答（REQ-06） | 固定用例集 | 每个 PR |
| 评测 | 测试集上的准确率与资源消耗 | `eval/` | 每个版本完成时，以及改动提示词时 |
| 压测 | 并发下的时延、失败率、降级比例 | Locust（V2b）、k6（V3） | V2b、V3 |

## 2. 评测测试集

**规模与分类**：共 200～300 题，分四类单独统计。

| 类别 | 内容 | 对应需求 |
|---|---|---|
| single | 单跳问题，标准问法 | REQ-01 |
| colloquial | 口语或同义表达 | REQ-02 |
| multi_hop | 两跳及以上的组合问题 | REQ-03 |
| no_answer | 图谱中确实没有答案的问题 | REQ-05 |

**构造方法**
1. 从图谱中采样路径（如 药物 → 禁忌 → 疾病），套用问题模板生成标准问法，标准答案直接从图谱中查出（实体集合）。
2. 让 LLM 把一部分标准问法改写成口语，构成 colloquial 类。
3. no_answer 类：使用图谱中不存在的实体组合，或问图谱中没有的关系。
4. 人工抽检 20%，修正或删除有问题的题目。
5. **冻结**：打上 `testset-v1` 标签后，四个版本共用这一份，不再修改。确实需要修订时另存一个新版本，并且所有版本都要用新版本重新跑一遍。

**存储格式**（`eval/dataset/testset-v1.jsonl`，每行一题）
```json
{"id": "T0001", "category": "single", "question": "二甲双胍有什么禁忌",
 "gold_entities": [{"name": "严重肾功能不全", "label": "Disease"}],
 "source_path": "(:Drug {name:'二甲双胍'})-[:CONTRAINDICATION]->(:Disease)"}
```

## 3. 指标

| 指标 | 计算方式 |
|---|---|
| 准确率 | 对每道题，比对 `done.answer_entities` 与 `gold_entities`，计算精确率、召回率和 F1，再按类别取平均；**完全命中率**（两个集合相等）单独报告 |
| 正确拒答率 | no_answer 类中，返回 `NO_INFO` 的比例 |
| 误拒答率 | 有答案的题目中，被错误返回 `NO_INFO` 或 `REFUSED` 的比例 |
| Cypher 执行成功率 | 生成的语句通过校验并执行成功的比例（含重写后成功的） |
| LLM 调用次数 / token 数 | 取 `done.usage`，按题目平均 |
| 时延 | 取 `done.latency_ms`，报告 P50、P95 和首字时延 |
| 路由级别占比（V2a 起） | 取 `meta.route_level` 统计分布 |

## 4. 对照组

| 版本 | 对照设置 |
|---|---|
| V1 | A 模板问答 · B LLM 直接回答 · C 本系统 |
| V2a | 消融：V1 基线 → + 模板通道 → + 缓存 → + Schema 裁剪 |
| V2b | 不同并发量下，会员和免费用户分别统计 |
| V3 | Python 网关与 Go 网关，使用同一个压测脚本 |

**说明**："LLM 直接回答"组不查图谱，没有 `answer_entities`。这一组改为从回答文本中抽取实体后再比对，并在报告中注明口径不同。

## 5. 缓存命中率的测试口径（V2a）

测试集中每道题只出现一次，测不出真实的缓存命中率。另外构造一组**重复请求流**：从测试集中按长尾分布抽样（少数热门问题反复出现），并按"同一模板、不同实体"进行替换。报告中注明这组数据是模拟的。

## 6. 评测环境要求

- 固定模型名称、版本和 temperature（评测时设为 0），写进报告。
- 每次评测记录代码的 commit 哈希和测试集版本。
- 原始运行结果放在 `eval/runs/`（不进入仓库），汇总后的报告放在 `docs/03-test/reports/`（进入仓库）。

## 7. 测试报告模板

报告放在 `docs/03-test/reports/<版本>-eval.md`，内容包括：环境（commit、模型、测试集版本）→ 各组、各类别的结果表 → 失败样本按错误类型分类 → 结论，以及对下一版的改进建议。
