# 立项说明

> 状态：初稿 · 2026-10-29 · 导师已同意课题方案（见 `课题优化方案_导师已确认.docx`）

## 要解决的问题

糖尿病患者和家属每天都会遇到"能不能吃""这个药有什么禁忌""有并发症还能不能用"这类问题。现有渠道各有缺陷：

| 渠道 | 问题 |
|---|---|
| 搜索引擎 / 健康网站 | 信息零散，质量参差，要自己筛选 |
| 通用大模型 | 回答流畅，但可能编造事实，也给不出依据 |
| 传统知识图谱问答（关键词 / 模板匹配） | 事实可靠，但只认固定问法，口语和组合问题答不了 |

## 方案

以公开学术数据集 DiaKG（41 份中文糖尿病指南与专家共识的实体关系标注）为主体，补充指南中的饮食知识，构建糖尿病知识图谱，在此之上引入大语言模型做"理解问题、转述结果"：
- **模型负责翻译**：把口语问题转成图谱查询（Text2Cypher），再把查询结果组织成自然语言。
- **知识只来自图谱**：每个回答都附上依据；图谱中没有的内容如实告知，不让模型编造。
- **守住医疗边界**：诊断、剂量类问题拒答，并提示就医。

## 目标用户

糖尿病患者本人（以 2 型为主）和照护者（家属）。产品是 ToC 形态，定位为健康科普工具。

## 为什么值得做

1. **学术**：有明确的对照实验（模板问答 / LLM 直答 / 本系统），能量化说明"图谱 + 大模型"的效果。
2. **工程**：按导师建议，研究"用尽可能少的资源达到相同效果"，以及不同优先级用户高并发下的调度，贴近企业实际需求。
3. **可复现**：图谱数据来自公开学术数据集并注明出处（CC BY-NC，见 ADR-0007）；模板问答系统自行实现，同时作为实验对照组和零成本的快速通道。

## 范围

| 做 | 不做 |
|---|---|
| 糖尿病相关的科普问答：饮食、用药禁忌、并发症、日常管理 | 诊断、开处方、调整剂量、急症处理 |
| H5 移动端（可选打包成微信小程序） | 原生 App |
| 小范围真实用户试用 | 公开上线运营（需要备案和资质） |

## 交付路线

V1 基础版（2027.01 底）→ V2a 省资源（2027.02）→ V2b 高并发调度（2027.03）→ V3 Go + Python（2027.03～04）。每个版本都能单独交付和答辩，详见 [架构设计](../02-design/architecture.md)。

## 主要风险

| 风险 | 预案 |
|---|---|
| DiaKG 同义实体未合并、"药物—疾病"关系不区分适用和禁用 | V1 第 2～3 周做实体归一化和关系细分：LLM 依据原句给出候选，人工抽检 |
| DiaKG 几乎没有饮食知识 | V1 第 4 周从指南饮食章节用 LLM 抽取，人工逐条校验后入库，每条注明出处 |
| 数据许可为非商业（CC BY-NC） | 不做真实收费；V2b 的会员等级只是模拟的调度优先级 |
| Text2Cypher 准确率不达预期 | 补充 few-shot 示例、细化 Schema 说明，按错误类型分析失败样本 |
| V2b、V3 时间不够 | 每个版本单独可交付；V2b 设了保底档 |
| 小程序门槛（备案、类目） | 退回 H5，试用效果不受影响 |
