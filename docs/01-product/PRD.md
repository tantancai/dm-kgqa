# 产品需求文档（PRD）

> 状态：初稿 · 2026-10-29 · 每个版本开工前修订；改需求先改这里，再开 Issue
> 需求编号 `REQ-xx` / `NFR-xx` 会在 Issue、PR、测试报告中引用，**编号一经分配就不再复用**（废弃的需求标记为"已废弃"）

## 1. 用户与场景

### 1.1 用户画像

| 画像 | 特点 | 主要诉求 |
|---|---|---|
| 患者本人 | 以 2 型糖尿病为主，中老年居多；常同时服用多种药物，可能合并并发症 | 问法口语化、要快，希望得到跟自己情况相关的答案 |
| 照护者（家属） | 替家人查询，对医学术语不熟 | 回答要看得懂、有依据，能放心照做 |

### 1.2 典型场景

| 场景 | 示例问题 |
|---|---|
| 饮食 | "血糖高能吃西瓜吗"、"糖尿病早餐吃什么好" |
| 用药 | "二甲双胍有什么禁忌"、"肾功能不全能用二甲双胍吗" |
| 并发症 | "有肾病的糖尿病患者不能用哪些药" |
| 日常管理 | "糖尿病要做哪些检查" |
| **超出边界** | "我这个指标是不是得糖尿病了"、"胰岛素该打几个单位" → 必须拒答并提示就医 |

### 1.3 不在范围内

诊断、开处方、调整剂量、急症处理；药物之间的相互作用（数据不覆盖）；非糖尿病领域的问题；原生 App；公开上线运营。

## 2. 功能需求

优先级：**P0** 本版本必须完成 · **P1** 应该完成 · **P2** 可选

### V1 基础版

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| REQ-01 | 自然语言单跳问答 | P0 | 测试集"单跳"类 F1 ≥ 0.90；全集按类别平均 F1 ≥ 0.80，且比模板问答（对照组 A）高 ≥ 15 个百分点 |
| REQ-02 | 识别口语和同义表达 | P0 | "血糖高"等口语能对应到图谱中的标准实体；测试集"口语"类 F1 ≥ 0.80 |
| REQ-03 | 多跳组合问题 | P1 | 测试集"多跳"类 F1 ≥ 0.65 |
| REQ-04 | 回答附图谱依据 | P0 | 每个基于图谱的回答都返回依据路径和出处原句，前端可以展开查看；回答中的引用编号必须都能对应到证据 |
| REQ-05 | 图谱无答案时如实告知 | P0 | 查询结果为空时返回 `NO_INFO`，不调用模型自由回答；测试集"无答案"类正确拒答率 ≥ 0.90 |
| REQ-06 | 安全护栏：诊断、剂量类问题拒答并提示就医 | P0 | 护栏测试用例全部拒答，返回 `REFUSED` |
| REQ-07 | 流式输出 | P1 | 回答逐段推送，记录首字时延 |
| REQ-08 | 移动端 H5 聊天界面 | P0 | 手机浏览器可以正常提问和查看回答 |
| REQ-09 | 免责声明常驻 | P0 | 页面底部始终显示免责声明 |
| REQ-10 | 三组对比实验 | P0 | 模板问答 / LLM 直答 / 本系统在同一测试集上的结果齐全 |
| REQ-24 | 饮食知识问答（"能不能吃"、"怎么吃"） | P0 | 饮食知识从指南中抽取，逐条人工校验并注明出处；测试集包含饮食题，单独统计 F1 |
| REQ-25 | 区分药物的适用与禁用 / 慎用 | P0 | "药物—疾病"关系细分为适用、禁用、慎用；人工抽检 ≥ 20% 且正确率 ≥ 95%；测试集中禁用、慎用类题目不得答反 |
| REQ-26 | 自研模板问答（对照组 A） | P0 | 关键词 + 规则匹配，覆盖单跳题型；与 AI 服务使用同样的函数接口；返回置信度，供 V2a 级别 1 使用 |

### V2a 省资源

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| REQ-11 | 分级路由：缓存 → 模板 → Text2Cypher | P0 | 各级别的占比可统计；准确率与 V1 相比基本不变 |
| REQ-12 | Cypher 缓存（缓存参数化查询，不缓存答案） | P0 | 缓存命中时 0 次 LLM 调用；统计误命中率 |
| REQ-13 | Schema 裁剪 | P1 | 提示词 token 数下降，且准确率不受影响 |
| REQ-14 | 数据库查询优化 | P1 | 慢查询经过 PROFILE 分析并优化，有优化前后的对比 |
| REQ-15 | 个人健康档案与个性化宜忌判断 | P2 | 结合用户正在用的药和并发症，在图谱上做多跳判断 |
| REQ-27 | 图邻域证据回退（级别 3） | P1 | Text2Cypher 查空时召回一跳邻居的出处原句，重排后带引用作答；单独统计回退命中率和引用正确率，不计入实体 F1 |
| REQ-16 | 打包成微信小程序，供真实用户试用 | P2 | 体验版可用；前提是完成域名备案（见 NFR-05） |
| REQ-23 | 多轮对话（例如"那它的禁忌呢"能理解"它"指什么） | P2 | 能结合上文补全被省略的实体 |

## 3. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 准确性 | 回答只能依据图谱查询结果；V2a 之后，全集平均 F1 比 V1 下降不超过 1 个百分点，任一类别下降不超过 2 个百分点 |
| NFR-02 | 性能 | 记录 P50 / P95 时延与首字时延；具体目标值在 V1 测出基线后确定 |
| NFR-03 | 安全 | 数据库只读访问；拒绝写操作语句；Cypher 参数化，防止注入；密钥不进入代码仓库 |
| NFR-04 | 隐私 | 健康档案属于敏感个人信息：使用前单独征得同意、加密存储、支持删除；试用前完成隐私政策 |
| NFR-05 | 合规 | 定位为健康科普工具，不提供诊断和处方；图谱数据许可为 CC BY-NC，不做任何真实收费；不公开上线运营；小程序需要 HTTPS 域名并完成 ICP 备案 |
| NFR-06 | 可观测 | 每个请求记录路由级别、LLM 调用次数、token 数、各阶段耗时（V2a 的对比基线依赖这些数据） |
| NFR-07 | 可演进 | 网关与 AI 服务只通过 `contracts/openapi.yaml` 通信，替换网关时其他部分不改动 |
